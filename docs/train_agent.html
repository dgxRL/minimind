1. Big picture

The script trains a MiniMind policy to use tools correctly. Each batch: sample num_generations multi-turn agent trajectories per prompt against mock tools, score them with a rule-based reward (+ optional InternLM2 reward model), compute a group-relative advantage (GRPO-style), and update the policy with a CISPO (default) or clipped-GRPO loss plus a k3-estimated KL penalty against a frozen reference model.

2. Multi-turn rollout — rollout_single

One trajectory = up to max_turns = 3 generate→parse→execute cycles. Thinking mode is randomly enabled per trajectory with probability thinking_ratio (default 0.1). Everything the model generates is logged with mask 1 and real per-token logps; everything the environment injects (tool results + re-prompting) gets mask 0 and logp 0 — so the policy gradient only trains on the model's own tokens.

rollout_batch runs this per prompt × num_generations (default 4), deep-copying messages each time. Generation happens under torch.no_grad(); logps come from the engine so the update step can form the importance ratio without re-decoding.

Gotchas. Mock tools are deterministic lookup tables plus a sandboxed eval for math (1s SIGALRM guard) — trajectories are self-play against fixtures, not a live environment. execute_tool's signal.alarm is POSIX-only. The dataset loader returns raw lists/dicts (custom collate_fn), and rollout_engine.update_policy must run after every load/save to keep generation in sync with training weights.
